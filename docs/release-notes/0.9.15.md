> [!NOTE]
> **This one is mostly repairs.** Fourteen of them, several found by reading the code and the log rather than by hitting them, and one proved in the log before it was touched. If 0.9.14 was the release that added a mode, this is the release that goes back over the app and fixes what was wrong underneath it.

## 🔄 New version notices come to you

The old ones did not, quite. A corner balloon appeared for four seconds, and if you were not looking at the screen at that moment there was nothing left to find: reaching the release notes meant opening settings and spotting a card on the Home page.

- **The notes now open on their own** when a new version is found. Escape or **Not now** leaves your version exactly as it is, and the offer stays on the Home page for as long as it applies.
- **The window is much bigger.** It was 520 pixels wide, which is the width of a question, holding text meant to be read. It now sizes its notes panel from the height of your screen.
- **Still never over a game or a session**, and it will not stack on top of the first-run welcome.

## 🖱️ Fixed: the buttons that were not there

**Reset all settings** and **Start Couch Session** were missing from the footer, and switching desk-only mode on and then off again made them appear.

The strip holding them measured itself by asking each button whether it was visible. A button inside a window that has not been shown yet always answers no, whatever it was set to, and all of that measuring happened while the window was still being built. So the strip sized itself to eleven pixels and the buttons were clipped off the edge. It keeps its own record now, which is right before the window exists as well as after.

## 🪟 Fixed: pop-ups that pinned everything in place

Nothing on screen could be moved while a dialog was up. Every pop-up here is drawn without a title bar, so none of them had anything to drag, and Windows disables the window underneath while a dialog it owns is open.

**Every dialog can now be dragged by its own body** — its heading, its text, or any empty part of it. Buttons, toggles and text boxes keep their clicks.

## 🌈 Fixed: HDR

- **The same two games were looked up on Steam, thrown away, and looked up again on every single launch.** One part of the file recorded the question without the answer; another part treated a question with no answer as damaged and discarded it. Two comments, each correct on its own, quietly cancelling each other out. The log had been saying so 26 times.
- **Turning Auto HDR off while playing left HDR on.** So did unticking your last game, and the game's raised process priority stayed raised with it. Nothing was left watching to undo either, so it took a restart. The watcher now reports the game as stopped when it is switched off, and everything unwinds.

## 🔒 Fixed: a switch that claimed more than it did

The Performance page offered **"Turn off User Account Control (UAC)"**. It does not do that, and never has. It sets Windows to never notify and forces UAC itself back on, so admin apps elevate without a prompt you cannot answer from the sofa.

That is still a real reduction in security and a materially smaller one than turning UAC off. The switch is now called **"Turn off UAC prompts"**, the status line says *"UAC prompts are off"* rather than *"UAC is off"*, and the README says the same.

## 🖥️ Fixed: your displays

- **The recovery file is kept when the restore fails.** If putting your displays back went wrong, the error was caught, logged, and then the file describing how to put them back was deleted anyway. The safety net was being thrown away in the one situation it exists for.
- **The log stopped claiming success it had not checked.** The same step waited for the displays, discarded the answer, and wrote *"Display topology restored."* either way.
- **The settings window no longer freezes on a display change.** It slept for four hundred milliseconds on the thread that draws it, once per change, and a session start makes several.

## 🎮 Fixed: closing a game the session could not name

The last-resort pass at the end of a session closes whatever is filling the television, on the strength of Steam reporting that *something* is running. Usually that is your game. A browser or a video player left full-screen fits the description too, and one refusing to close was being ended outright after eight seconds.

That pass now asks, and takes no for an answer. Every other close is unchanged, because everywhere else the process has actually been identified as the game.

## 📸 The README has pictures now

Real ones, of the session prompt over a running game, the first-run question, the settings pages and the HDR list.

## 💻 Getting it

> [!WARNING]
> **Windows will warn you the first time.** `CouchSession.exe` is not code signed, so SmartScreen shows *"Windows protected your PC"*. Click **More info**, then **Run anyway**.

Windows 10 or 11. No installer and no runtime to install. Download `CouchSession.exe` below and run it.

If you are already running 0.9.14, this one will show itself to you.
