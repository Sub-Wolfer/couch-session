> [!NOTE]
> **Two new features and a hard look at what happens around a running game.**
> Couch Session can now free up memory by closing the apps you choose, and show you exactly what a session will do before it does it. Underneath that, a long evening of testing on real hardware fixed a set of faults around games that were already running when a session began.

## 🧹 New: free up the machine

A browser, a chat client and a music player are gigabytes of memory and a steady trickle of background work that nobody is using from the sofa. Pick the apps you want out of the way, under **Performance ▸ Freeing up the machine**, and they close when a session starts and open again when it ends.

**They are asked, never forced.** Each one gets the same close request Alt+F4 sends. An app that refuses, which usually means it has something unsaved, is left running and the log says so. Nothing here ever ends a process, and that is a deliberate limit rather than a missing feature.

- **Choose from what's open**, in a table with the memory each app is holding, sorted heaviest first. Or point at an executable yourself with Browse.
- **The shell, Steam and Couch Session can never be closed**, whatever you pick. Anything running as administrator isn't offered, because this app runs without those rights and could not close it anyway.
- **Two browser windows closed come back as two.** Your tabs and documents don't; Windows offers no way to ask an app to reopen what it had.
- **Works at a desk too.** In desk-only mode it hangs off a game starting rather than a session, the same rule the power plan already follows there.

## 👀 New: see what a session will do first

**Preview session**, in the footer, lists every change starting a session would make, worked out from your settings as they stand rather than from a list of features. A setting that's off produces no line.

The column that matters is on the right: what becomes of each thing when the session ends. *Desktop comes back. Sound comes back. HDR goes off. Those apps are opened again*, or *left closed*. Green where it returns to how it was, amber where it doesn't.

Anything that would stop a session working comes first, in warning colour, and the button to start one isn't offered while that's true.

## 🌈 Fixed: HDR now follows your main display

Start a game you've ticked at your desk, then begin a session while it's still running, and HDR moves with the picture: off on the monitor, on for the TV. Quit the game and it goes off where it actually is.

It used to record only *that* it had switched HDR on, never *where*, so it switched off whatever was primary at the time. The result was HDR going off on the TV and your monitor left washed out with nothing saying why.

Three separate faults were behind this, each found by testing on a real two-monitor setup:

- **Switching HDR made Windows re-apply its saved display arrangement**, bringing a disconnected desk monitor back and handing it primary mid-session.
- **The display was named twice** — once inside the HDR call, once afterwards — and those answers stopped agreeing precisely because the HDR change moved the primary between them.
- **A "nothing to do" shortcut returned success silently**, leaving no trace in the log for the step that was failing.

## 🎮 Fixed: games that were already running

- **The game moves to the TV**, at the TV's size. It used to be brought to the front but never moved, so in TV-only mode the monitor was disconnected out from under it.
- **And back to your monitor's size afterwards**, so a game left running doesn't return as a 1920×1080 window on an ultrawide.
- **A game is told apart from its launcher by name.** DOOM Eternal keeps `idTechLauncher` running behind the game at the same size as a 1080p TV, so it was the launcher being moved. Size was never going to separate them.
- **A game that puts itself back after a display change is asked again**, for up to ten seconds, rather than once.

## ⚡ Also

- **"Only when plugged in"** leaves the power plan alone on battery, checked once as a session starts. Only shown on machines that have one.
- **The main session button** uses the app's own violet instead of a green that belonged to no part of the palette, with a quieter gradient and glow.
- **Shortcut symbols follow your controller.** With no pad connected they used to fall back to Xbox buttons; they now use the last controller seen, taken from one the app already knows about so it's right on a cold start.
- **Wider pages**, and **Reset all settings** moved from the footer to General, where it gets a sentence rather than a tooltip.

## 💻 Getting it

> [!WARNING]
> **Windows will warn you the first time.** `CouchSession.exe` is not code signed, so SmartScreen shows *"Windows protected your PC"*. Click **More info**, then **Run anyway**.

Windows 10 or 11. No installer and no runtime to install. Download `CouchSession.exe` below and run it.

If you are already running 0.9.15, the app will show you this on its own.
